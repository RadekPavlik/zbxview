Push notifications: step-by-step setup

Android · ZbxView 0.50+ · Zabbix 6.4–8.0 · about 30 minutes, done once by the Zabbix admin

ZbxView has no cloud of its own, so your Zabbix sends notifications through a free Firebase project that belongs to you. You set this up once. After that, each technician only scans a QR code.

What you are building

The “relay” is a small program that you install on the Zabbix server. Firebase only accepts messages signed with a private key, and a Zabbix webhook cannot sign them. So Zabbix hands each alert to the relay, and the relay signs it and passes it to Firebase. It is not something you find or click in Firebase.

  1. Before you start
  2. Create the Firebase project
  3. Install the relay on the Zabbix server
  4. Connect Zabbix to the relay
  5. Add the project to the QR code
  6. Scan the QR code and test
  7. If something does not work

Part 1Before you start

  • An Android phone with ZbxView 0.50 or newer. Your own Firebase project cannot deliver to iPhones, because that needs the app developer’s Apple key.
  • SSH with sudo on the machine that runs the Zabbix server. This is not necessarily the machine that runs the web frontend.
  • A Zabbix account with the Super admin role.
  • Python 3.9 or newer on the server. Check with python3 --version.
  • Outgoing HTTPS from the server to fcm.googleapis.com and oauth2.googleapis.com at all times, and to pypi.org and github.com during installation.
Running Zabbix in Docker? Read the Docker row in the troubleshooting table first, because the relay address is different.

Part 2 · In your browserCreate the Firebase project

You need two files from Firebase. Keep them apart, because they do different jobs:

FileGoes toSensitive?
google-services.jsonThe ZbxView connect module in Zabbix (Part 5)No, it only identifies the project
service-account.jsonThe Zabbix server only (Part 3)Yes, it is a private key. Never put it on a phone or in git.

2.1 Create the project

Open console.firebase.google.com, click Create project and give it any name. Google Analytics is not needed. The free Spark plan is enough.

2.2 Add the Android app and download google-services.json

  1. On the project overview page, click the Android icon (or Add app).
  2. In Android package name, enter exactly app.zbxview. Firebase does not check who owns the package, so this is fine.
  3. Click Register app.
  4. Click Download google-services.json.
  5. Skip the remaining wizard steps. They are for developers, and you do not need to add anything to any code.

2.3 Generate the private key

  1. Click the gear icon, then Project settings, then the Service accounts tab.
  2. Click Generate new private key and confirm with Generate key.
  3. Rename the downloaded file to service-account.json. Firebase gives it a long name such as myproject-firebase-adminsdk-abc12-1234567890.json, and the relay will not find it under that name.

Part 3 · On the Zabbix server, over SSHInstall the relay

Run the blocks below one at a time, in order. Use the Copy button and paste them into your SSH session instead of retyping them.

Most of these commands print little or nothing when they succeed. That is normal. Step 3.6 tells you whether the relay is really working.

3.1 Debian and Ubuntu only: install the Python venv package

Skip this on RHEL, Rocky, Alma and Oracle Linux.

sudo apt install -y python3-venv

3.2 Download the relay

sudo mkdir -p /opt/zbxview-push-relay
cd /opt/zbxview-push-relay
for f in push_relay.py config.ini.example zbxview-push-relay.service; do
  sudo curl -fsSLO https://radekpavlik.github.io/zbxview/tools/push-relay/$f
done
ls

You should see:

config.ini.example  push_relay.py  zbxview-push-relay.service

3.3 Put the private key on the server

Run this on your own computer, in the folder with the file, replacing the user and server name. On Windows, WinSCP works too.

scp service-account.json youruser@your-zabbix-server:~/

Then, back on the Zabbix server:

sudo mv ~/service-account.json /opt/zbxview-push-relay/

3.4 Create the configuration and a shared secret

The shared secret is a password between Zabbix and the relay. This block generates one and writes it to the configuration. Copy the secret it prints, because you need it in step 4.2.

cd /opt/zbxview-push-relay
SECRET=$(openssl rand -hex 24)
sudo cp config.ini.example config.ini
sudo sed -i "s/FILL_ME_LONG_RANDOM/$SECRET/" config.ini
echo "Your shared secret: $SECRET"

3.5 Install the Firebase library and start the service

The installation takes a minute or two. A pip warning about upgrading is harmless.

cd /opt/zbxview-push-relay
sudo python3 -m venv venv
sudo venv/bin/pip install firebase-admin
sudo chown -R zabbix:zabbix .
sudo chmod 600 config.ini service-account.json
sudo cp zbxview-push-relay.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now zbxview-push-relay

3.6 Check that the relay works

sleep 5
systemctl is-active zbxview-push-relay
SECRET=$(sudo awk -F' *= *' '/^shared_secret/{print $2}' /opt/zbxview-push-relay/config.ini)
curl -s -X POST -H "X-Auth: $SECRET" -d '{}' http://127.0.0.1:8090/send; echo

You should see exactly this:

active
{"ok": false, "error": "missing token"}

That “error” means success. The relay is running, it accepted your secret, and it is only complaining that this test named no phone. If you see anything else, go to troubleshooting.

3.7 RHEL, Rocky, Alma, Oracle Linux: allow Zabbix to reach the relay

Run getenforce. If it prints Enforcing, SELinux has to allow Zabbix to connect to the relay port:

sudo setsebool -P zabbix_can_network on

Part 4 · In the Zabbix web interfaceConnect Zabbix to the relay

4.1 Import the media type

  1. Download media_type_zbxview_push.yaml to your computer.
  2. In Zabbix, open Alerts → Media types and click Import.
  3. Choose the file and click Import.

The file is for Zabbix 7.0 and newer. On 6.4, create a webhook media type named exactly ZbxView Push by hand, using this script and the parameters listed at its top.

4.2 Enter the shared secret

  1. Click ZbxView Push in the list.
  2. Replace the value of the Auth parameter with the secret from step 3.4. You can show it again with sudo grep shared_secret /opt/zbxview-push-relay/config.ini.
  3. Leave RelayURL as http://127.0.0.1:8090/send, unless Zabbix runs in Docker.
  4. Click Update.

4.3 Test Zabbix → relay

In the media types list, click Test in the ZbxView Push row, leave the values as they are and click Test. This test sends to a phone that does not exist, so it is expected to fail. The message tells you how far it got:

Message containsMeaning
relay HTTP 502 or relay HTTP 400Good. Zabbix reached the relay and the secret is correct. Continue.
relay HTTP 401The Auth value does not match shared_secret. Repeat step 4.2.
Couldn't connect or similarZabbix cannot reach the relay. See step 3.6, step 3.7 and the Docker row in troubleshooting.

4.4 Create the action

The action decides which problems are sent, and to whom.

  1. Open Alerts → Actions → Trigger actions and click Create action.
  2. Name it, for example ZbxView push. Add conditions if you want to limit it, for example Trigger severity is greater than or equals High.
  3. On the Operations tab, under Operations, click Add. Choose your technicians in Send to user groups or Send to users, set Send to media type to ZbxView Push and click Add.
  4. Under Recovery operations, click Add, choose Notify all involved and click Add. Technicians then also get a “Resolved” notification.
  5. Click Add to save the action.

You do not enter any phone numbers or addresses. The app registers each phone with Zabbix by itself in Part 6, and Zabbix only sends a user problems on hosts that user has permission to see.

Part 5 · Server and Zabbix web interfaceAdd the project to the QR code

This part is required. The phone has to learn which Firebase project to use, and the QR code from the free ZbxView connect module tells it. Until then, the app shows no Push notifications option at all. (With an MDM you can send the same values as push_* keys instead.)

5.1 Install the ZbxView connect module

Skip this if you already have version 1.6 or newer. On the machine that runs the Zabbix web frontend:

cd /usr/share/zabbix/modules
sudo git clone https://github.com/RadekPavlik/Zabbix-UI-Modules-ZbxView-connect.git

If that folder does not exist, use /usr/share/zabbix/ui/modules. Then, in Zabbix, open Administration → General → Modules, click Scan directory and enable ZbxView connect.

5.2 Load the project

  1. Open Administration → Mobile configuration.
  2. On the Push notifications (Firebase) card, click Load google-services.json and pick the file from step 2.2. The four values fill in.
  3. Click Save.

Part 6 · Every technician, on their phoneScan the QR code and test

6.1 Pair the phone

  1. In Zabbix, in your own account, open User settings → Mobile connect. A QR code appears.
  2. In the app, choose Add server → Scan QR code. If the server is already in the app, scan the code anyway.
  3. When Android asks about notifications, tap Allow.
  4. If the app tells you to restart it, close it fully and open it again.

Push turns on by itself after the scan. To confirm, check that Settings → Push notifications is on in the app.

6.2 Confirm Zabbix registered the phone

In Zabbix, open Users → Users, choose your user and open the Media tab. There should be a ZbxView Push row with a long token. Each phone has its own row.

6.3 Send a real test

Raise a test problem on a host you can see that matches the action, for example by stopping the agent on a lab host or lowering a trigger threshold for a moment. A notification should arrive, and tapping it opens the problem.

That completes the setup. Your other technicians only need 6.1, as long as the action in step 4.4 includes them.

Part 7If something does not work

Two places tell you nearly everything. On the server, this shows the relay’s log:

sudo journalctl -u zbxview-push-relay -n 30 --no-pager

In Zabbix, Reports → Action log shows whether an alert was sent and the error if it failed. Python FutureWarning and DeprecationWarning lines in the relay log are harmless.

During installation

What you seeCause and fix
ensurepip is not available or venv/bin/pip: command not foundThe Python venv package is missing. Do step 3.1, run sudo rm -rf /opt/zbxview-push-relay/venv, then repeat step 3.5.
curl or pip times outThe server has no direct internet access. Go through your proxy: export https_proxy=http://proxy:port, and use sudo -E instead of sudo.
failed or activating in step 3.6, log shows FileNotFoundError ... service-account.jsonThe key is missing or still has its long name. See steps 2.3 and 3.3, then run sudo chown zabbix:zabbix /opt/zbxview-push-relay/service-account.json and sudo systemctl restart zbxview-push-relay.
curl prints nothing in step 3.6The relay is not running or not started yet. Wait a few seconds and retry, then check the log.
Zabbix runs in DockerInside a container, 127.0.0.1 is the container and not the host. In config.ini, set listen to the host’s IP address and restart the relay. Set RelayURL in the media type to the same address, and allow only the Zabbix container to reach port 8090.

On the phone

What you seeCause and fix
No Push notifications option in SettingsThe phone has no Firebase project yet, or it is an iPhone. Finish step 5.2, then scan a new QR code. Codes made before step 5.2 do not contain the project.
“Zabbix did not take the registration”The media type is missing or not named exactly ZbxView Push, or your account may not change its media. Fix it and turn the switch off and on again.
No ZbxView Push row in the user’s Media tabThe phone was scanned before Part 4 was done. Turn the Push notifications switch off and on again.

Nothing arrives after a test problem

What you seeCause and fix
Nothing in Reports → Action logThe action did not run. Check that it is enabled, that its conditions match, and that the user can see the host. If the action sends to a user group, make sure the user is in it.
relay HTTP 502 with invalid_grantFirebase rejected the private key. The key was deleted, or the server clock is wrong. Check the time, generate a new key (step 2.3) and restart the relay.
relay HTTP 502 mentioning a sender or project mismatchservice-account.json and google-services.json come from different Firebase projects. Both must come from the same one.
relay HTTP 410The phone’s token is no longer valid. Turn the Push notifications switch off and on again.
Action log says Sent, but no notificationCheck that notifications for ZbxView are allowed in Android settings, and that battery saving is not restricting the app.

Still stuck? Use the contact form and include the output of step 3.6, the relay log and the error from the Action log. Do not send service-account.json, config.ini or the shared secret.
